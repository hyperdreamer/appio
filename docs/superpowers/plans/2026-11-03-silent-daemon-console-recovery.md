# Silent Daemon Console Recovery Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use the deterministic
> subagent-driven-development controller to implement this plan task-by-task.
> Steps use checkbox (`- [ ]`) syntax. The controller owns progress; leave every
> box unticked and do not edit this file during a pinned run.

**Goal:** Keep the last applied history frame visible and honestly labelled while reads are slow or retired, distinguish daemon-answer failures from retention evidence, and add observed causes beneath the existing owner-state banner.

**Architecture:** `CollectorCoordinator` invalidates only when the source-selection key changes and reports successful local sample commits to `CollectorWindow`. `HistoryRouter` exposes unsettled local work and a typed display-only remote failure, while render models keep that diagnostic separate from contract coverage. `CollectorWindow` owns sample coalescing and one gated, rate-limited preparation path; the same derived stall text drives Overview and Files without changing the retained table.

**Tech Stack:** Python `>=3.14`, existing PyQt6 `>=6.6`, standard-library dataclasses, `concurrent.futures`, pytest, and pytest-qt. No new runtime dependency.

### Authority and Lane

- Behavioural authority: `docs/superpowers/specs/2026-11-03-silent-daemon-console-recovery-design.md`, sections 1-9.
- Implementation contract: `docs/superpowers/specs/2026-11-03-silent-daemon-console-recovery-spec.md`; its exact interfaces, transitions, strings, test names, and exclusions govern this plan.
- One sequential lane: `recovery`. Tasks 1-7 run in order because each task consumes the preceding module contract and several tasks edit `tests/p3/test_collector_window.py`. No parallel lanes are declared.
- File ownership is limited to the six production modules and four test modules listed below. Ranges identify planning-baseline areas; symbol names in each task remain authoritative after earlier edits shift line numbers.

## Global Constraints

- Python floor is `>=3.14`; retain the existing runtime dependency `PyQt6>=6.6` and do not change either requirement in `pyproject.toml`.
- The five fixed state strings (`off`, `on, answering`, `enabled, not answering`, `on, needs activation`, `unavailable`) and every other ratified vocabulary stay byte-identical.

The existing Overview/Files tab, single-subject behavior, A22 refusal strings, owner-state strings, and retention semantics remain in force.

- Produces `PENDING_BUDGET_NS: int = 30 * 10**9` and fields `_pending_since: int | None`, `_stalled: bool`, `_retry_after: int | None`, `_deferred_target: Window | None`; retain `_refresh_after_apply` from Task 6.
- All submissions, including `show_window`, pass through `_submit_prepare(wanted, origin: Literal["clock", "explicit"])`. One pass submits at most once, with `wanted = _deferred_target or _target`, only if `_pending is None`, `local_read_in_flight is False`, the retry floor is absent/elapsed, and `wanted` exists. Initial load remains admitted.

**Seven state-machine rules:**

1. Accepting a preparation sets `_pending` and `_pending_since = now`, clears `_stalled` and `_retry_after`, retains a different deferred target, and arms the existing readiness poll.
2. At the inclusive deadline `now - _pending_since >= PENDING_BUDGET_NS`, set `_stalled = True`; keep the pending read, displayed frame, and router generation unchanged.
3. When an unavailable router retires a non-None pending scope, capture `wanted`, clear `_pending` and `_pending_since`, set `_retry_after = now + PENDING_BUDGET_NS`, preserve `_stalled`, and do not submit in that transition. Repeated retirement observation does not restart the floor. An unavailable router with no pending scope creates no floor.
4. A submission pass is admitted only when `_pending is None`, `local_read_in_flight is False`, `_retry_after is None or now >= _retry_after`, and `wanted` exists. It submits at most one preparation. A queued Future is in flight because it is unsettled.
5. Derive the label on every status update. When stall labeling is eligible and the local read is unsettled, use `history read has not completed (<view_state>); the reader is still busy`. Otherwise, while the floor is future, use `history read has not completed (<view_state>); retrying in <n> s`, with positive ceiling seconds computed by integer arithmetic. At/after the floor, remove the retry label. Before stall eligibility, retain `loading history (<view_state>)` or `updating (<view_state>)`.
6. Clear `_pending` and `_pending_since` together when a frame applies; clear `_stalled` and `_retry_after` on accepted preparation or applied frame. Clear `_deferred_target` only when the exact deferred scope is applied. A committed tick flag is consumed only by `_apply_frame()` after normal rendering/Files synchronization; clear it and invalidate exactly once inside `files_view.transient_scope()`. Do not prepare inline. An explicit request arms/replaces `_deferred_target` but never changes `_target`, `_pending_since`, `_stalled`, `_retry_after`, or a busy caption. Applying A cannot clear deferred B.
7. Every preparation entry point, including clock retry, `show_window`, `apply_ready_frame`, and initial load, obeys the same gate. No path outside `_submit_prepare` calls `history.prepare()`.

`now` is one `_clock_ns()` value per evaluated transition. The deadline follows elapsed time, not scope identity. `show_window(window)` runs the gate during that call when eligible; otherwise B remains deferred while A stays pending.

**Preparation failures:** A current-call `WindowUnavailableError` from prepare precheck propagates unchanged and creates no retry marker, pending read, stall, or floor, regardless of prior `view_state`; preserve the ratified A22/validation text verbatim with no `appio:` prefix. Any other prepare exception records `PrepareRetry` with the submission origin and shows `appio: <str(error)>`, or the exception class name when empty. Clock-owned retry is gate-controlled; explicit-owned failure is retried only by a later `show_window(marker.window)`, while a different window supersedes it. Neither failure creates a retirement floor or sets `_stalled`; Recheck never retries history.

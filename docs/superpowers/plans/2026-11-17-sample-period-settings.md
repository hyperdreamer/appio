# Adjustable Sample Period Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use the deterministic
> subagent-driven-development controller to implement this plan task-by-task.
> Keep the checkboxes unticked in the pinned plan and record progress in the controller.

**Goal:** Implement the approved D1–D13 system-service sampling-period setting with durable application, accurate observations, and executable acceptance coverage.

**Architecture:** The daemon resolves its period once at production startup and reports the actual constructor value in its status response. The existing fixed-argv privileged helper owns the canonical systemd drop-in and a durable pending/completed journal. The settings UI requests a period through that helper and reports the effective value from a fresh collector probe. A filesystem-foundation commit precedes the single atomic commit that introduces both the seventh boundary verb and its dispatcher.

**Tech Stack:** Python, PyQt6, pytest, pytest-qt, SQLite, systemd, and existing injected clock, filesystem, subprocess, and IPC seams.
